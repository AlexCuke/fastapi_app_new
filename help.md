# Помощь по структуре проекта

Проект представляет собой асинхронный интеграционный сервис на FastAPI с локальным веб-интерфейсом, поддержкой запросов к внешнему API, хранением шаблонов команд и экспортом данных из Elasticsearch в PostgreSQL.

## Корневая директория

- `main.py` — точка входа приложения FastAPI.
  - Создаёт экземпляр `FastAPI` с `lifespan`, который инициирует подключение к базе и необходимые таблицы.
  - Подключает маршруты `config`, `commands`, `export`.
  - Отдаёт HTML-страницы `index`, `settings`, `services`.

- `README.md` — общая инструкция по установке и запуску.
- `requirements.txt` — список Python-зависимостей.
- `Dockerfile` / `docker-compose.yml` — контейнеризация приложения.
- `hosts` — дополнительные хосты/сервисы (в проекте может использоваться для локального тестирования).
- `output_PA.csv`, `sort_index.csv`, `sort.csv` — файлы, используемые для экспорта и структуры данных.

## Папка `app/`

`app/` содержит основную серверную логику и модули.

- `app/config.py` — конфигурация приложения через Pydantic Settings.
  - Настройки внешнего API, Elasticsearch, PostgreSQL и файловых путей.
  - Загрузка переменных из `.env`.

- `app/db.py` — управление подключением к PostgreSQL.
  - `DatabaseSessionManager` создаёт пул соединений.
  - `get_db()` предоставляет зависимость FastAPI для доступа к базе.

- `app/db_ops.py` — операции с базой данных.
  - Инициализация таблиц, CRUD для конфигурации, импорт CSV, синхронизация данных, генерация метаданных.

- `app/api_client.py` — помощь для работы с внешним API.
  - Подстановка маркеров вида `@config:<key>` и `@now_iso`.
  - Отправка асинхронных HTTP-запросов через `httpx`.

- `app/elastic_export.py` — логика экспорта из Elasticsearch.
  - Получение документов, преобразование вложенных структур, сохранение JSONL/CSV.
  - Запись данных в таблицы `index`, `index_final` и `keys`.

- `app/models.py` — реэкспорт моделей из корневого `models.py`.
  - Используется для определения входных/выходных схем.

- `app/default_templates.py` — набор встроенных шаблонов команд.
  - Хранит список команд и payload-шаблонов для выполнения.

- `app/routers/` — маршруты FastAPI.
  - `config.py` — настройка приложения, получение настроек, статус-трекер процедур.
  - `commands.py` — управление командами, получение списка шаблонов, выполнение команд, разрешение маркеров.
  - `export.py` — эндпоинты для импорта CSV, импорта схем, копирования данных и запуска экспортных задач.

## Директория `templates/`

- `index.html` — главный веб-интерфейс для работы с командами и payload.
- `commands.html` — отдельная страница для редактирования таблицы `request_templates` и сохранения шаблонов в БД.
- `settings.html` — страница настроек приложения.
- `services.html` — дополнительная страница сервисов/документации.

## Виртуальное окружение

- `env/` — локальный Python virtualenv с установленными зависимостями.
  - Этот каталог не обязательно держать в репозитории, но он уже присутствует в рабочем дереве.

## Как использовать проект

1. Активировать виртуальное окружение.
2. Установить зависимости (если нужно):
   ```bash
   pip install -r requirements.txt
   ```
3. Запустить сервис:
   ```bash
   uvicorn main:app --reload
   ```
4. Перейти в браузере:
   - `http://localhost:8000/` — веб-интерфейс.
   - `http://localhost:8000/docs` — OpenAPI документация.

## Ключевые особенности

- Интерактивное выполнение команд на основе заранее определённых шаблонов.
- Подстановка значений из конфигурации с маркерами `@config` и `@now_iso`.
- Асинхронная работа с PostgreSQL и внешним API.
- Экспорт данных из Elasticsearch в локальные CSV/DB таблицы.
- Веб-интерфейс для настройки и управления.

## Основные таблицы БД

- `config`
  - Хранит пары `key` / `value` для параметров приложения и шаблонов.
  - Дополнительно содержит `group_name`, чтобы можно было классифицировать связанные параметры или группы команд.
  - Используется при подстановке маркеров `@config:<key>` в командных payload.

- `request_templates`
  - Хранит шаблоны команд с полями `name`, `method`, `path`, `payload` и `group_name`.
  - `group_name` обозначает группу команды и позволяет классифицировать шаблоны.
  - Заполняется дефолтными значениями из `app/default_templates.py` при первом запуске.

- `status_tracker`
  - Ведёт историю изменений статусов назначений и процедур.
  - Содержит `assignment_id`, `procedure_code`, `assignment_status`, `procedure_status`, `trigger_command`, `last_updated`.

- `index`
  - Основная таблица, куда загружаются данные из CSV или экспортируются из Elasticsearch.
  - Используется для синхронизации состояния текущих назначений и построения `current_assignment`.

- `index_final`
  - Таблица результирующего представления данных после приведения к схеме `sort_headers`.
  - Создаётся из `index` с выравниванием колонок по заявленной структуре.

- `keys`
  - Таблица ключей/колонок, сформированных по метаданным из `sort_headers`.
  - Заполняется из `index` по отсортированному списку заголовков.

- `sort_headers`
  - Хранит сопоставление заголовков колонок и целевых файлов/таблиц.
  - Используется при формировании структуры `index_final` и других табличных экспортов.

- `settings`
  - Хранит метаданные схем файлов (`filename` и `headers`), импортируемые из `sort.csv`, `sort_index.csv` и других описаний.
  - Используется для генерации справочных метаданных и загрузки схем.

- `current_assignment` и `currrent_assignment`
  - Временные таблицы, создаваемые из `index` по `assignmentCompositionUid`.
  - Служат для быстрого доступа к актуальным данным текущего назначения.
