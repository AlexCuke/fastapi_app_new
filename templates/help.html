🚀 Введение

API Integration Service — асинхронный интеграционный сервис на базе FastAPI. Он предоставляет веб-интерфейс для выполнения предопределённых команд (шаблонов запросов) к внешнему API, подстановки конфигурационных переменных, отслеживания статусов назначений и экспорта данных из Elasticsearch в PostgreSQL.

Сервис автоматически инициализирует все необходимые таблицы в PostgreSQL (config, request_templates, status_tracker, elastic_index, index_final, current_assignment, sort_headers, keys, settings).

🧱 Архитектура

📁 Структура проекта

  • main.py — точка входа FastAPI, lifespan, маршруты HTML.
  • app/ — бизнес-логика: db.py, db_ops.py, api_client.py, elastic_export.py, default_templates.py.
  • app/routers/ — эндпоинты: config.py, commands.py, export.py.
  • templates/ — HTML-интерфейсы (index.html, settings.html, commands.html, services.html, current_patient.html, index_db.html).

🔌 Внешние зависимости

  • PostgreSQL — хранение конфигураций, шаблонов, данных из Elasticsearch.
  • Elasticsearch — источник данных о назначениях и процедурах.
  • Внешний API — выполнение команд (например, /api/v1/procedure/planProcedure).
  • httpx — асинхронные HTTP-запросы.
  • asyncpg — работа с PostgreSQL.

🖥️ Главный интерфейс (/)

Основная рабочая панель для взаимодействия с командами:

  • Левая панель — список всех команд, сгруппированных по group_name. При клике загружается шаблон payload в редактор.
  • Быстрый поиск — поле Composition UID для выполнения команды «Найти назначение по CompositionUid (GET)».
  • Payload Editor — редактирование JSON-тела запроса (с поддержкой маркеров).
  • Переменные — автоматически извлекаются из payload (маркеры @config:... и @now_iso). Позволяют вручную задать значения перед отправкой.
  • Трассировка — отображает отправленный запрос, ответ от API, а также текущие статусы назначения и процедур (из трекера).
  • Авто-выгрузка индекса — при успешном выполнении команды через 15 секунд автоматически запускается экспорт из ES в БД.
💡 Совет: При успешном ответе от API (200/201) сервис автоматически обновляет значения ключевых конфигураций (assignmentCompositionUid, code, workplaceId, doctorName, doctorJob) в таблице config и пересоздаёт current_assignment.

🔄 Переменные и подстановка маркеров

В payload команд можно использовать специальные маркеры, которые будут заменены реальными значениями:

@config:assignmentCompositionUid → значение из таблицы config с ключом assignmentCompositionUid
@now_iso → текущая дата/время в формате ISO (UTC) с миллисекундами.

Страница Настройки (раздел «Параметры конфигурации БД») позволяет редактировать все @config: переменные. Также поддерживается вложенная подстановка в объектах и массивах.

На главной странице в блоке Переменные автоматически отображаются все маркеры из текущего payload. Вы можете ввести временные значения, которые будут применены при нажатии «Применить переменные → JSON», без сохранения в БД.

📤 Экспорт из Elasticsearch

Страница Сервисы предоставляет кнопки для работы с Elasticsearch и локальными файлами:

  • Выгрузить индекс из ES — запускает фоновую задачу, которая читает все документы из индекса settings.INDEX_NAME, разворачивает вложенные структуры (procedureAssignment.elements), сохраняет .jsonl и .csv (файлы OUTPUT_JSONL, OUTPUT_CSV), а затем загружает данные в таблицы elastic_index и (опционально) index_final.
  • Выгрузить keys из ES — аналогично, но заполняет только таблицу keys на основе извлечённых данных.
  • Создать keys из index — генерирует таблицу keys на основе уже существующей elastic_index (без обращения к ES).

Статус последнего экспорта можно отследить через эндпоинт /export/status (отображается в трекере главной страницы).

⚙️ Параметры подключения к Elasticsearch (ES_HOST, INDEX_NAME, SCROLL_SIZE) настраиваются в файле .env или через веб-интерфейс настроек.

⚙️ Страница настроек (/settings)

Позволяет изменять системные параметры и управлять метаданными:

  • Tenant / User ID — значения, передаваемые в заголовках X-Tenant-Id и X-User-Id при вызове API.
  • Параметры конфигурации БД — все ключи из таблицы config с возможностью изменения значения и группы.
  • sort_headers — выбор файла (elastic_index / index_final) и заголовка для назначения пользовательского отображаемого имени (поле name), которое используется в заголовках таблиц на страницах /index-db и /current-patient.
  • Внешний API / Elasticsearch / PostgreSQL — полный перечень настроек из .env (можно сохранить, после чего сервер автоматически перезапишет .env и перезагрузит конфигурацию).
  • Сервисные опции — быстрые действия: импорт CSV в elastic_index, обновление схемы столбцов (sort_headers), синхронизация index → index_final, обновление таблицы settings.

🛠️ Дополнительные сервисные функции

📥 Импорт локального CSV

Загружает содержимое файла OUTPUT_CSV (по умолчанию output_PA.csv) в таблицу elastic_index, полностью заменяя её.

📄 Обновление схемы столбцов

Читает файлы sort.csv и sort_index.csv (разделитель ;) и заполняет таблицу sort_headers. Используется для корректного отображения заголовков и порядка колонок в index_final.

🔄 Синхронизация index → index_final

Копирует данные из elastic_index в index_final, выравнивая колонки согласно схеме из sort_headers (порядок и наличие полей).

📁 Обновление таблицы settings

Создаёт/обновляет таблицу settings, в которой хранятся имена файлов схем и списки их заголовков (из sort.csv, sort_index.csv, keys.csv).

⚠️ Устранение неполадок

❌ Не удаётся подключиться к PostgreSQL

Проверьте параметры DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD в файле .env или на странице настроек. Убедитесь, что сервер БД запущен.

❌ Маркер @config:... не заменяется

Убедитесь, что соответствующий ключ существует в таблице config. На странице настроек (раздел «Параметры конфигурации БД») можно добавить недостающий ключ.

❌ Экспорт из Elasticsearch не работает

Проверьте доступность ES_HOST, корректность INDEX_NAME. Убедитесь, что в индексе есть документы с полем data.procedureAssignment. Логи фоновой задачи выводятся в консоль сервера.

💡 Логирование и отладка

Запустите сервер с uvicorn main:app --reload --log-level debug для детального вывода. Все операции с БД и запросы к API логируются.
